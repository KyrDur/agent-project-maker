## Codebase Patterns (Jensen M2 Slice A, 2026-05-18)
- Alembic 迁移 SQLite 兼容: 使用 `sa.Uuid()` (PG/SQLite 均兼容)。`op.create_index(..., postgresql_where=...)` 仅在 PG 中创建 partial index；SQLite 测试通过 ORM 的 `Base.metadata.create_all` 路径，因此无影响。
- 循环 FK (`marketplace_items.latest_version_id` ↔ `marketplace_versions.id`): 在 m40 中 (1) 创建 items(无 FK) → (2) 创建 versions → (3) ALTER ADD FK。ORM 使用 `mapped_column(ForeignKey(..., use_alter=True, name=...))` + `relationship(..., post_update=True)`。若无 `use_alter=True`，SQLite create_all 会出现 SAWarning("Can't sort tables for DROP")，因此 ORM 侧也需显式指定 use_alter。
- 保留字 `metadata`: 列名仍为 `metadata`，但 attribute 按 `metadata_json: Mapped[dict | None] = mapped_column("metadata", JSON, ...)` 模式分离。
- ruff UP037: 使用 `from __future__ import annotations` 时，所有 forward ref 均 unquoted。已自动 fix — TYPE_CHECKING import 也可转换为 unquoted。
- 使用 SQLAlchemy 2.0 `selectinload(MarketplaceItem.latest_version)` 时，如果 latest_version_id 为 NULL，也需要 lazy fallback (None 检查后 db.get)。
- router mount 验证: `uv run python -c "from app.main import create_app; app = create_app(); [r.path for r in app.routes if 'marketplace' in r.path]"` — 如果没有 import error，则 mount 成功。
- SkillResponse origin/publication embed: ORM → Pydantic 转换后直接赋值追加字段，如 `response.origin_summary = ...`。`model_config = {"from_attributes": True}` 只映射 ORM 字段，我们模块的字段保持原样。
- 第一阶段 Alembic verify 需要 PostgreSQL (已有 `natural-mold-postgres-1` Up)。如果 docker 未运行，执行 `docker-compose up -d postgres`。
- `_serialize_skill` helper 位置: router 模块内，在 `router = APIRouter(...)` 声明之后。ruff isort 有时会把 router 声明移到 import 块后，因此需明确保持 router 声明位于函数定义之前。

## Bezos Test Patterns (M2.5 listing 更正, 2026-05-19)
- 默认 `GET /items` default 行为符合 Spec §10.1: 普通用户仅 owner+system+listed-public+restricted-ACL，super_user 为全部。
- `?is_listed=true` 与 default 是 **不同结果** — explicit filter 与 visibility scope intersect，因此 owner items 中 is_listed=False 的项会被排除。测试中若假定两者相同则会 fail。
- `?is_listed=false` 结果 set 大小取决于 user role: super_user 为所有未批准 public，regular user 仅为自己 owned 的未批准项 (绕过 owner clause)。
- 即使显式指定 `visibility=unlisted` filter，也不会包含在 list 响应中 — 因为 service `_base_catalog_query` 的 visibility_clauses 中没有 unlisted。detail 访问是通过 `can_view_item` 的独立路径。
- access test 仅依赖 predicate(`can_view_item`)/detail(`GET /items/{id}`) 层，因此不受 list 行为变更影响。predicate 对 `unlisted+published` 返回 True 与 detail-link sharing 的意图一致。
- Agent 构造器不接收 `slug`/`tools_config`/`assistant_enabled` 参数。测试中直接创建 Agent 时仅使用 `id/user_id/name/description/system_prompt/model_id`。

## Codebase Patterns (Pichai 补充)

- `Cross-user credential` collapse 为 `CREDENTIAL_NOT_FOUND` 404 (防止 leak 其他 user 的 cred 是否存在)。`system credential` + `definition_key mismatch` + `unknown requirement_key` 为 422 `MARKETPLACE_CREDENTIAL_MISMATCH` (用户自身的意图错误 — 可暴露具体原因)。
- DELETE binding 为 idempotent 204 — 与是否存在无关 (rules/security.md，防止 enumeration channel)。`await db.commit()` 仅在实际删除行时调用。
- 测试 fixture 中使用 `client` fixture 会强制 super_user + 绕过 CSRF。通过 `db: AsyncSession` fixture 直接创建 ORM 行。`TEST_USER_ID` 用户通过单独的 `_make_test_user(db)` helper 创建 (满足 skill/credential 的 FK)。
- `installation.status` derivation: 如果 DB 的 `install_status='active'` 且 `missing_required_keys` 非空，则响应中升级为 `'needs_setup'`。`disabled`/`uninstalled` 是显式状态，因此保持。

## E2E 隔离 DB + colima 端口转发 gotcha (2026-06-12)
- 这台机器的 docker 不是 Docker Desktop，而是 **colima**。新 publish 的容器
  端口可能不会转发到 macOS host (VM 内部正常，但只有 host nc 失败)。
  - 诊断: 若 `colima ssh -- bash -c 'echo > /dev/tcp/127.0.0.1/<PORT>'` 成功，但
    host `nc -z localhost <PORT>` 失败，则是 colima forwarder 缺失。
  - 恢复: `colima ssh-config > /tmp/cfg && ssh -F /tmp/cfg -f -N -L <PORT>:127.0.0.1:<PORT> colima`
  - 清理: forwarding 注册到 colima 的 SSH ControlMaster(mux)，因此即使杀掉 client process
    listener 仍会保留。`ssh -O cancel -L <PORT>:127.0.0.1:<PORT> -S ~/.colima/_lima/colima/ssh.sock lima-colima`
- live E2E 用隔离 DB recipe (禁止对共享 DB 执行 alembic 约束的安全绕行):
  1. `docker run -d --name moldy-e2e-pg -e POSTGRES_USER=moldy -e POSTGRES_PASSWORD=moldy -e POSTGRES_DB=moldy -p 5433:5432 postgres:16`
  2. 在 worktree `backend/.env` 写入 throwaway secrets (DATABASE_URL 5433,
     ENCRYPTION_KEY/JWT_SECRET 使用 `openssl rand -hex 32`)
  3. `cd backend && uv run alembic upgrade head` (通过 downgrade 往返也可验证新增 migration 对称性)
  4. `cd frontend && E2E_FRONTEND_PORT=3100 E2E_BACKEND_PORT=8101 pnpm playwright test e2e/smoke.spec.ts`
     (3000/8001/5432 被其他 checkout·project 占用 — 使用替代端口以避免 reuseExistingServer 陷阱)
  5. 清理: `docker rm -f moldy-e2e-pg` + 删除 worktree `backend/.env` + cancel ssh forwarding
- smoke.spec.ts 是定期 suite。UI 结构变化(侧边栏整合等)导致 smoke 失败时
  应从 source 判断"回归 vs 过时 assertion"后更新测试。dropdown menuitem
  通过 portal 渲染，因此应在 page 层级查找，而非 main scope。
- 侧边栏/根 layout 组件只能在 client 使用 ROOT_MESSAGE_NAMESPACES(appSettings, auth,
  common, metadata, nav, sidebar)
  (src/i18n/scoped-messages.tsx)。若引用 chat.* 这类 page scope namespace，
  会出现 runtime IntlError — vitest 注入完整 ko.json 因此捕获不到，只有 E2E 的
  console-error assertion 能捕获。侧边栏新增 copy 时应放到 sidebar.* 下。
