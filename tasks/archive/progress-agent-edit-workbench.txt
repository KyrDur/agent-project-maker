## M1（jensen）— Backend opener_questions

### 实现结果
- migration：`m16_add_opener_questions`（m15 → m16）。`agents.opener_questions JSON nullable`。round-trip OK。
- model：`Agent.opener_questions: Mapped[list[str] | None]`（`JSON, nullable=True, default=list`）— 完全沿用 `middleware_configs` 模式。
- schema：`AgentCreate`/`AgentUpdate`/`AgentResponse` 3 处均为 `opener_questions: list[str] | None`。共享 validator `_validate_opener_questions` 校验 ≤12 项 + strip 后 1~200 字符。validator 对空字符串/空白 strip 后 reject（阻止空项）。正常项规范化为 strip 后的值。
- service：在 `create_agent`/`update_agent` 中各反映一行。
- router：在 `_agent_to_response` 中新增 `opener_questions` 字段。
- test：新增 4 个（create+update+roundtrip / 13 项 reject / 空字符串 reject / 201 字符 reject）。全部 pytest 628 PASS，ruff clean。

### 模式/注意事项
- **AgentCreate/Update 使用 `extra='forbid'`**：新增字段时如果未同时注册到两个类，会产生 422。两者都必须注册。
- **Pydantic v2 `field_validator` + `@classmethod`** decorator 顺序：`@field_validator(...)` 在上，`@classmethod` 在下。
- **共享 validator**：在 `Create`/`Update` 中都使用相同校验逻辑时，拆成 module-level helper 并从两个类中调用即可 DRY。
- **router**：`_agent_to_response()` 是 ORM → Response 转换的单一路径。新增响应字段时若此处遗漏，响应中不会携带。
- **PUT API**：router 使用 `PUT /api/agents/{id}`（不是 PATCH）。测试也使用 PUT。
- **ruff I001**：在 import block 后立即新增 module-level 常量时，空行 2 个会整理为 1 个（用 `--fix` 解决）。
- **用空列表 `[]` PUT** 时因 `is not None` 会正常清空为空列表。JSON 列 default=list，所以新 row 可能不是 `[]` 而是 `None`（DB column nullable）— 响应中原样暴露为 `null`。

### FE 契约
- `Agent.opener_questions: string[] | null`（在 Zuckerberg M6 中同步）
- `AgentUpdate { opener_questions?: string[] }` — 发送 undefined 则不变，发送 `[]` 则清空，`null` 可通过 PATCH 清空（当前 server-side validator 允许 `None` 通过，因此无变更）

## M7 HOTFIX (zuckerberg)

### MAJOR 1 — 阻止 VisualSettingsFlow dual-save
- 新增 `embedded?: boolean` prop。`embedded=true` 时不渲染内部 `<Toolbar>` 本身（Toolbar 内 Save 按钮 + 返回/Undo/Redo 全部隐藏 — workbench header 持有唯一 Save）
- 新建 `controlledState`/`controlledHandlers` props。两者都提供时 `isControlled = true` → 使用 props 替代内部 useState fallback
- 模式：`const name = isControlled ? controlledState!.name : internalName` + `const setName = isControlled ? controlledHandlers!.onNameChange : setInternalName`。按 hooks 规则 useState 始终调用（即使变量 unused 也 OK）
- agent prop sync useEffect 在 `isControlled` 时 early return — 页面 owns，因此忽略
- visual 模式中工具/技能/middleware 切换、模型/名称/描述/指令/参数修改全部流入 workbench page state → 单一 Save PUT 所有修改
- 独立路由 `/agents/[id]/visual-settings/page.tsx` 不传 `embedded` → 保持现有 internal state + Toolbar 行为（无回归）

### MAJOR 2 — TestChatPanel 提示 banner
- 在组件顶部新增 amber 色调 info banner（border-amber-200 + bg-amber-50，支持 dark mode）
- 韩语硬编码（scope 限定）。行为仍为 streamAssistant

### Gotcha
- 按 hooks 规则，`useState` 必须始终在 isControlled 分支前调用 → internal state 在 controlled mode 中也存在于内存（ignored）。微小内存成本 vs early-return 分支复杂度 trade-off → 选择简单性
- 在 `handleAgentNodeUpdate` 的 deps 中加入 `setX` 函数。controlled 修改时该函数会重新计算并让 AgentNode re-render，但函数引用仅在 isControlled 切换时变化，因此频率低
