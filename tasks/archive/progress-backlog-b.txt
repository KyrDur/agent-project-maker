## 失败教训

- M1 修改（允许 `update_tool_auth_config` 使用 CUSTOM）时，`tests/test_tools_router_extended.py::test_update_auth_config_non_prebuilt_returns_404` 被判为回归。该测试前提（=拒绝 CUSTOM）属于有意反转，因此"不是回归" — 已更新为验证新行为（其他用户 CUSTOM → 404 IDOR）。以后遇到类似语义反转修改时，建议第 1 次先 grep 匹配的现有测试（e.g. `non_prebuilt`、`not in.*PREBUILT` 等关键词）。
- 新测试直接借用 `test_update_mcp_server_credential` 模式（monkeypatch encryption._get_fernet → None、Credential seed、PATCH 验证、拒绝其他 user_id）。CUSTOM 没有 `_seed_mcp_server_with_tools` 之类 helper，因此 inline seed。
- (M2) `frontend/tests/components/tool/add-tool-dialog.test.tsx` 中验证 `Bearer` radio + `sk-xxx` placeholder 的 2 个测试因移除 inline auth 而失败。已按新 credential UI（默认无认证 + payload 不含 credential_id）更新，恢复 11/11 PASS。与 M1 相同模式 — 语义反转时先用 keyword grep 找潜在失败测试更高效。
- AddToolDialog 的 MCP/custom 两个标签页共享 `CredentialFormDialog`。由于 `onCreated` callback 只有一个，需要追踪由哪个标签页打开 — 通过 `credentialTarget: 'mcp' | 'custom'` state 分支处理。一个 dialog 被两个 trigger 共享时可泛化的模式。
