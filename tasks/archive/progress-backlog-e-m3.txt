## 项目目的

M1 创建了 `connections` 表 + CRUD API，M2 将 MCP 工具迁移为经由 connection。M3 中让 PREBUILT 工具按 per-user 标准使用各自 credential。当前结构引用 `tools.credential_id`（共享 row）→ 用户 A 的 credential 会暴露给用户 B。

**M3 完成后**: PREBUILT 工具执行通过 `tool.provider_name + current_user → default connection → credential` 路径工作。同一个 seed tool 可由多个用户使用各自 credential 执行。

## ADR-008 / M0 合议应用规则

- **新增 Tool.provider_name**: PREBUILT 必填（seed 时赋值），MCP/CUSTOM 为 NULL
- **Connection default 解析**: user_id + type='prebuilt' + provider_name + is_default=true（每用户、每 provider 1 个）
- **保持 env fallback**: 没有 default connection 时 `cred_auth = {}` → 保持现有 `settings.naver_*` 等路径（ADR-008 §11）
- **mock user seed**: Alembic m10 中 env 值 → credential → 自动创建 default connection（幂等）
- **Legacy fallback**: 原则上 PREBUILT 忽略 `tools.credential_id`，但到 M6 前仅对 `provider_name IS NULL` 情况保留现有路径（迁移 tolerance）
- **Cross-tenant guard**: `assert_connection_ownership` / `assert_credential_ownership` 已在 M2 引入 — PREBUILT 也复用

## 高风险点

1. **get_agent_with_tools 的 default connection 预加载** — 防止 PREBUILT tool 每个产生 N+1 查询。按 user_id 的 provider_name list 进行 1 次 IN 查询，映射为 dict。
2. **env fallback 有效性** — 没有 connection 时必须传递 `auth_config=None` 或 `{}`，让 tool builder 使用 env 值。
3. **mock user seed 幂等** — 第二次 upgrade 或在其他 PROD 执行时禁止重复创建。
4. **frontend 3 个 dialog 集成** — 在不回归现有功能的情况下替换。add-tool-dialog/tool-card 调用处也连锁更新。
5. **禁止触碰 CUSTOM 分支** — `tool.credential_id` CUSTOM 路径属于 M4 工作。
