## 项目目的

到 M3 为止，PREBUILT 工具通过 per-user default connection 解析 credential。M4 也将**CUSTOM 工具**迁移为经由 `tool.connection_id`。当前 CUSTOM 引用 `tool.credential_id` 共享 row（PR #55 M3 完成时基于 `_resolve_legacy_tool_auth` 路径）。

**M4 完成后**: CUSTOM 工具执行时通过 `tool.connection.credential` 解密。共享同一 credential 的多个 CUSTOM tool 以 N:1 共享 1 个 connection。tool.credential_id / tool.auth_config 作为 legacy fallback 保留到 M6 drop。

## ADR-008 / exec-plan §4 M4 应用规则

- **CUSTOM Connection 形式**: `type='custom'`, `provider_name='custom_api_key'`, `extra_config=NULL`, `display_name=credential.name`, `is_default=true`, `status='active'`
- **N:1 共享原则**: 引用同一 credential 的多个 CUSTOM tool 共享同一个 connection（m11 按 `(user_id, credential_id)` 去重）
- **Legacy fallback 到 M6**: 若 `tool.connection_id IS NULL AND tool.credential_id` 存在，则走现有 `_resolve_legacy_tool_auth` 路径 — M6 cleanup 时移除
- **Fail-closed 策略（与 PREBUILT M3 相同）**: 已指定 `tool.connection_id` 时 connection disabled / credential=NULL → raise `ToolConfigError`（不退回 env fallback）
- **Cross-tenant guard**: 复用 `assert_connection_ownership` / `assert_credential_ownership`（M2 引入，M3 扩展）

## Alembic m11 详细设计

### 对象识别
```sql
SELECT id, user_id, credential_id FROM tools
WHERE type = 'custom'
  AND credential_id IS NOT NULL
  AND connection_id IS NULL;
```

### 迁移流程（幂等）
1. 将上述结果按 `(user_id, credential_id)` distinct 分组。
2. 对每组：
   - 现有 `connections` 表中是否存在 `(user_id, type='custom', credential_id, display_name LIKE '[m11-auto-seed]%')`？
   - 若存在则**复用**（取得 conn_id）。
   - 若不存在则**insert**：
     ```
     id = uuid4()
     user_id = tool.user_id
     type = 'custom'
     provider_name = 'custom_api_key'
     display_name = f'[m11-auto-seed] {credential.name}'
     credential_id = tool.credential_id
     extra_config = NULL
     status = 'active'
     is_default = true
     ```
3. 将组内所有 tool 的 `connection_id` UPDATE 为对应 conn_id。

### downgrade
1. 对 `display_name LIKE '[m11-auto-seed]%'` 条件的 connection，将 tool.connection_id 反向设置为 NULL。
2. DELETE 这些 connection。
3. 不触碰手动创建的 CUSTOM connection。

### revision ID
- 文件名：`m11_custom_credential_migration.py`
- revision：`m11_custom_connection`（21 字符 — PG VARCHAR(32) 安全）
- down_revision: `m10_prebuilt_connection`

### 注意
- 使用 PostgreSQL native SQL 时无法在 aiosqlite 测试执行 → 像 M9/M10 precedent 一样拆成 helper 函数，pytest 仅通过 `inspect.getsource` guard 验证。实际 round-trip 在 PG 执行。
- `M11_SEED_MARKER = "[m11-auto-seed]"` 常量定义在 migration 文件顶部后写入 display_name。

## 高风险点

1. **credential 共享 → 1 个 connection**（N:1 shared）。m11 按 `(user_id, credential_id)` dedup。用测试强制。
2. **Legacy fallback 路径** — 现有 CUSTOM tool 在 `connection_id IS NULL` 状态执行不得回归。保留 chat_service._resolve_legacy_tool_auth 路径。
3. **Fail-closed 策略** — 有 `connection_id` 但 disabled/credential=NULL → `ToolConfigError`。禁止退回 env fallback（PREBUILT 有 env fallback，但 CUSTOM 本来就没有 env，无法工作）。
4. **ownership mismatch** — CUSTOM 有 `tool.user_id NOT NULL` + `connection.user_id NOT NULL` + `credential.user_id NOT NULL` 3 重 guard。防御 DML 失误。
5. **add-tool-dialog find-or-create UX** — credential 选择 → connection 自动创建流程不应对 user-facing 可见。不是事务而是 2-step（connection POST 成功后 tool POST），失败时 orphan connection 处理转入 M5。
6. **禁止 M5 drive-by** — custom-auth-dialog.tsx 用于现有 tool credential re-bind，但 M4 不替换。仅通过 Legacy 路径工作。
