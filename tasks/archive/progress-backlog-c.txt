# progress.txt — feature/credentials-field-keys-cache（Backlog C）

团队共享记忆。此前工作的 progress 已 archive 到 `tasks/archive/progress-backlog-b.txt`。

## 工作上下文

`GET /api/credentials` 对每个 row 的 `data_encrypted` 进行 Fernet 解密 + JSON 解析后暴露 `field_keys` → N+1 解密。新增 `credentials.field_keys` 列（非加密缓存），无需解密即可仅返回 key 名称。

**计划文件**: `~/.claude/plans/c-credentials-list-glistening-kurzweil.md`

## 预先确认的事实（Phase 1 探索结果）

- `credential_service.list_credentials`（line 16-24）：ORM only，无解密
- `credential_service.extract_field_keys`（line 98-103）：调用 `resolve_credential_data()` → `decrypt_api_key()` → N+1 原因
- `credential_service.create_credential`（line 42-66）：line 55 加密，此处也必须保存 `field_keys` cache
- `credential_service.update_credential`（line 69-82）：在 `data.data is not None` 分支中同步
- router `_to_response()`（credentials.py:23-35）：无需修改 response schema
- response schema `CredentialResponse`（schemas/credential.py:21-32）：保留 `field_keys: list[str]` 字段
- Alembic head: `m6_add_credentials` (backend/alembic/versions/m6_add_credentials.py)
- `sa.JSON()` 是项目惯例（agent_tools.config、builder_sessions.*、models.input_modalities 等）
- ENCRYPTION_KEY 已在 `.env` 中设置 — backfill migration 中可使用 `app.services.encryption.decrypt_api_key`

## 已确定的设计（用户 confirm）

| 项目 | 决策 |
|---|---|
| 列名 | `field_keys`（model、response schema 同名 — 自然） |
| 列类型 | `sa.JSON()` nullable=True（PostgreSQL JSONB 映射，兼容 SQLite） |
| Backfill 策略 | **migration upgrade() + runtime fallback 并行**（用户选择） |
| extract_field_keys | cache 优先，NULL 时解密 fallback（兼容 legacy） |
| 测试 | 新建 `test_credentials.py`（现有测试分散） |

## Gotchas（截至目前）

- decorator `sa.JSON()` 在 PostgreSQL 映射为 JSONB，但禁止显式使用 JSONB（项目惯例）
- migration 中可以 `from app.services.encryption import decrypt_api_key`，但失败时以 `[]` tolerant 处理
- aiosqlite 测试环境：即使运行 backfill migration，空表 → 无影响
- response schema 不变（兼容 API 消费者）
- ENCRYPTION_KEY 未设置的环境中 migration 跳过（因为 create 在返回 503 的环境中也会被拒绝）
