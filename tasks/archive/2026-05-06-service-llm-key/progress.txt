### M10 (Daily Spend Queue + Aggregate API + Model Fallback, backend)

- `services/spend_writer.py` — `SpendEntry` dataclass + `DailySpendUpdateQueue` (asyncio.Queue + 后台 drain task)。核心决策:
  - 用单一队列处理 3 个 axis (若拆分，producer 必须 enqueue 3 次)
  - flush trigger: 达到 `flush_interval_sec=5.0` 或 `batch_size=100` 时
  - drain: `wait_for(queue.get(), timeout=interval)` → greedy `get_nowait` until batch_size → `_flush_batch`
  - `_flush_batch`: 按 axis 将 entries 以 `(date, target_id)` group → 对各表执行 dialect-aware `INSERT ... ON CONFLICT (date, target_id) DO UPDATE SET total_X = X + EXCLUDED.X` (PG/SQLite)。其他 dialect 使用 application-level upsert fallback。
  - producer (`add()`) 非阻塞: `put_nowait` (QueueFull / RuntimeError 时 warning + drop，不阻止 agent 执行)。
  - `stop()` graceful: flush 队列剩余项 → task cancel → await (with `contextlib.suppress`)。
  - 模块全局 `spend_queue` singleton。
- `hooks/builtin/spend_hook.py` — 在 `agent_invoke` post hook 中执行 `spend_queue.add(SpendEntry(...))`。0 token / 0 cost row 会 skip (interrupt 等异常结束 guard)。failure isolation 由 HookRegistry + 自身 try/except 双重 guard。
- 在 `register_default_hooks()` 中添加 SpendHook → 现在为 `["logging_hook", "audit_hook", "spend_hook"]` (`test_hooks.py` 同步更新)。
- `main.py` lifespan — `spend_queue.start()` (seed+checkpointer 之后、scheduler 之前) + `spend_queue.stop()` (scheduler shutdown 之后、checkpointer shutdown 之前)。
- `agent_runtime/streaming.py` — 给 `stream_agent_response` 添加 `usage_sink: dict | None`。stream 结束时将 captured `prompt_tokens/completion_tokens/estimated_cost` in-place update 到 sink dict。

## Phase 1 → Phase 2 核心决定（ADR-012 §3, §4）

### ResumeRequest dual-shape (transition)
```python
class Decision(BaseModel):
    type: Literal["approve", "edit", "reject", "respond"]
    edited_action: dict | None = None  # type=edit
    message: str | None = None         # type=reject | respond

class ResumeRequest(BaseModel):
    decisions: list[Decision] | None = None  # 标准（新增）
    response: str | list[str] | dict | None = None  # @deprecated，转换为单个 respond decision
    # 两者至少一个必填 — 用 model_validator 验证
```

### INTERRUPT event payload dual emit
```typescript
// 标准（新增）
{ event: 'interrupt', data: {
  action_requests: [{ name, args, description? }],
  review_configs: [{ action_name, allowed_decisions: ('approve'|'edit'|'reject'|'respond')[] }]
}}
// legacy（保留，在 transition window 期间一起 emit）
{ event: 'interrupt', data: { interrupt_id, value: { type, question?, options?, message? } } }
```
streaming.py 对一个 task 的一个 interrupt 发出两个 SSE chunk（标准 + legacy）。
frontend 优先处理标准，legacy fallback。两个 chunk 指向同一 interrupt，因此
需要防止重复处理的逻辑（e.g. 收到标准 chunk 后忽略 legacy chunk — 按同一 interrupt_id 判断）。

### Multi-action queue（仅标准）
- 标准 `action_requests` 长度 ≥ 1。长度 1 时单 action = 与现有行为等价。
- 长度 ≥ 2 时 frontend 以 array queue 渲染（Phase 2 先简单实现为顺序 card + 批量确认按钮）。

### trigger mode
- Phase 1 中，当 `include_ask_user=False` 时已经通过 `interrupt_on=None` 阻断。标准 middleware 实例本身不会被注入。**Phase 2 中 trigger 路径无额外变更。**

- 核心决定：
  1. _ENV_DEFAULTS snapshot 模式 = idempotent sync 的关键。每次调用先恢复 .env 再叠加 credentials layer → DELETE 时自然反映 key 缺失（无需单独 pop 逻辑）。采用 ADR-013 决定 3 中方案 (a)。
  2. 单 query 解决 priority：order_by(is_system DESC, created_at DESC) + dict 保留 first hit → 避免 N+1。system>user priority 在 SQL 层决定。
  3. _maybe_sync_env_fallback 的 is_llm_definition guard = 避免 naver_search/http_bearer 等 non-LLM CRUD 每次支付全量 LLM credentials decrypt 成本。兼顾性能 + 明确意图。

- 回归：881 PASS（现有 865 + 新增 16）。ruff 0 / pyright 0/0 / alembic OK。
- 学习点：
  1. mutable dict in-place mutation = 保持 alias 的标准做法。若像 `_ENV_FALLBACK = {...}` 那样替换对象，import 时持有 alias 的模块（builder helpers, system_credential_resolver）会保留 stale reference。只能用 `.clear() + .update()` 或 `.update(new)`。
  2. snapshot-then-layer 模式比 sync invalidate 更简单。与其在 3 个 CRUD handler 中分别写"key 增加/删除"逻辑，不如让 sync 函数每次重建 full state → 单一入口、单一意图、single source of truth。
