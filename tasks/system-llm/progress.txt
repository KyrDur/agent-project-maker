## API 契约（萨提亚确认 — 詹森/扎克伯格共识基准）

role enum: `text_primary` | `text_fallback` | `image`

GET  /api/system-llm-settings        (super_user)
  → 200: [ SystemLlmSettingOut x3 ]
PUT  /api/system-llm-settings/{role} (super_user)
  body: { "credential_id": uuid|null, "model_name": str|null }
  → 200: SystemLlmSettingOut
  - 指定 credential_id 时: 验证 is_system=True && definition_key ∈ {openai,anthropic,openrouter,openai_compatible}。
    违反时 404（不存在）/422（类型不允许）— 为防止 enumeration oracle，统一消息。

SystemLlmSettingOut:
  { role: str, credential_id: uuid|null, credential_name: str|null,
    provider: str|null (=credential.definition_key), base_url: str|null,
    model_name: str|null, configured: bool, updated_at: datetime }

discover（复用现有实现，禁止修改）:
  POST /api/credentials/{credential_id}/discover-models → 模型列表

- LLM credential definition_key: anthropic, openai, openrouter, openai_compatible (definitions/__init__.py).
- migration head: m44 (ADR-018)。新增为 m45，确认 down_revision='m44_relative_storage_path'。

## S2 测试预审（贝索斯, 2026-05-26 — 基于 test_system_llm_settings.py 11 PASS）

缺口（→传给詹森 '?'）:
- HIGH 缺少 require_super_user negative 测试: conftest client fixture 始终 is_super_user=True+CSRF bypass(L108,132)。无法验证普通用户 GET/PUT 被拒绝(403/404) → 需要添加 non-super client fixture 或 raw_client+真实 JWT。虽然是 ADR决策4 的核心 guard，却未验证。
- HIGH 缺少 credential ON DELETE SET NULL 行为测试 + aiosqlite 未设置 PRAGMA foreign_keys=ON（conftest engine L44，无 connect listener）→ 即使添加测试也不会触发 SET NULL。必须用 event.listens_for(engine.sync_engine,"connect") 开启 PRAGMA，才能形成有意义的回归 guard。
- MEDIUM 缺少 role UNIQUE 约束的直接测试（重复 role insert→预期 IntegrityError）。SQLite UNIQUE 即使没有 FK pragma 也会 enforce，因此可以添加。
- MEDIUM 缺少 CHECK(role IN) DB 级测试 — 当前 test_put_unknown_role_404 只验证 router。建议直接 insert role="bogus"→IntegrityError，以确认 defense-in-depth。
- MEDIUM 404/422 detail 一致性 assert 较弱: 两边只检查 substring("system LLM credential")，未验证 byte-identical → 即使 422 消息变化也会通过。建议捕获两个响应的 detail 后做 == assert，加强 enumeration oracle 回归 guard。
- LOW 缺少 updated_at PUT 更新测试。
