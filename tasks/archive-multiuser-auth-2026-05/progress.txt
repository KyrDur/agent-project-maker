## API 契约 (后端 → 前端接口)
- POST /api/auth/register {email, password, name} → {user, csrf_token} + Set-Cookie
- POST /api/auth/login {email, password} → {user, csrf_token} + Set-Cookie
- POST /api/auth/logout → {ok} + Clear-Cookie
- POST /api/auth/refresh → {csrf_token} + Set-Cookie
- GET /api/auth/me → {user: {id, email, name, is_super_user, created_at}}
- 所有 mutation 必须有 X-CSRF-Token header (auth/login, auth/register, auth/refresh 除外)
- 收到 401 响应时，frontend 尝试 1 次 /refresh → 失败则 redirect 到 /login
- credentials: 'include' 始终 (HttpOnly cookie 自动附带)

## 编写 ADR-016 时发现的决策模式 (Pichai)
- **用 CHECK constraint 强制 `is_system` 一致性**: `(is_system=FALSE OR user_id IS NULL)` — 在 DB 层阻止代码 bug 将 user_id 写入 system resource。tools/credentials 两侧同样应用。Jensen 将在 m22 migration 中通过 ALTER TABLE ADD CONSTRAINT 加入。
- **refresh replay 防御 = 废止该 user 全部 token**: rotation 时仅 revoke 旧 row 不够。检测到已 revoked token 被重复使用时，批量 revoke 该 user 的 active refresh，强制重新登录。若只返回简单 401，攻击者仍可用其他 token 继续尝试。
- **首位注册者 super_user 在 production 中有风险**: 通过 `ALLOW_FIRST_USER_AS_ADMIN=true` 环境变量可切换，并在 .env.example 中明确警告"运营者注册后立即改为 false"。Bezos 纳入 migration guide，Jensen 在 .env.example 添加注释。

## 设计/实现决策 (Zuckerberg — 前端 S5)

- **Next.js 16 convention**: `middleware.ts` 已 deprecated。Next 16 起命名为 `proxy.ts` + `export function proxy()`。参考 `node_modules/next/dist/docs/01-app/01-getting-started/16-proxy.md`。行为相同。
- **(auth) route group 暴露**: Next.js 的 route group 不影响 URL，因此只需将 `/login`, `/register` 等绝对路径加入保护矩阵。必须在 proxy 的 PUBLIC_ROUTES 中显式注册。
- **Bare layout 分支**: `AppLayout` (client component) 通过 `usePathname()` 检测 `/login` `/register`，不显示侧边栏，仅渲染 children。(auth)/layout.tsx 在其内部用 2 列 grid 布置表单卡。
- **CSRF 内存 + cookie fallback**: `lib/auth/csrf.ts` 中 in-memory 为 primary，`moldy_csrf` cookie 为 fallback (页面刷新后 SPA 启动时)。login/register/refresh 响应 body 中的 `csrf_token` 由 `useAuth` 通过 `setCsrfToken()` 保存。
- **401 dedup**: `apiFetch` 收到 401 后用单一 `tryRefresh()` promise 同步所有并发请求。成功则原请求 retry 1 次，失败则只触发一次 fireSessionExpired() (1 秒 dedup) → toast + queryClient.clear() + `/login?callbackUrl=…` redirect (保留 current path，拒绝以 // 开头)。
- **Auth endpoint whitelist**: `/api/auth/login`, `/api/auth/register`, `/api/auth/refresh` 不自动附加 CSRF header，且排除在 401 refresh flow 外。`/api/auth/logout` 需要 CSRF (依赖 backend verify_csrf)。
- **OnboardingDialog 模式**: 为规避 React 19 `react-hooks/set-state-in-effect` 规则，outer 只根据 props 决定 mount，inner 使用 `key={user.id}` + `useMemo(() => shouldShow(user), [user])` 计算初始 open。不在 effect 中 setState。
- **Super user welcome toast**: 单独 hook `use-super-user-welcome-toast.ts` — effect 中只调用 sessionStorage flag + toast.success (无 state sync)。created_at 在 5 分钟内视为 fresh 条件。
- **shadcn 未安装组件**: 项目中没有 Alert/Avatar/Form/Label → AuthAlert 改用 lucide + token-based inline 组件。Avatar 用 initials 函数生成 div。Form/Label 也使用 native `<label>` + Input 直接组合 (未安装 react-hook-form/zod — 避免新增依赖)。
- **PasswordStrengthMeter 评分规则**: 基于长度的简单 heuristic (8/10/14/18 字符) + 字母数字符号混合 bonus。zxcvbn 可之后替换引入。
- **session-expired handler 注册模式**: `lib/api/client.ts` 的 setSessionExpiredHandler(handler) 不是 React context，而是 module-level 变量。`QueryProvider` 在 useEffect 中注册/解除。这样 fetch layer 可在无 React 依赖的情况下触发 toast/redirect。
- **必须 Suspense**: Next.js 16 中 `useSearchParams()` 若在 page 直接调用会出现 prerender error。必须用 `<Suspense fallback={null}>` 包裹 (login/page.tsx)。

## 事务边界 + 强制 commit (jensen S7 escalation fix)
- **模式**: router/service 中更新 counter/state(UPDATE) 后，在 raise 前必须 `await db.commit()`。FastAPI 的 `get_db` 依赖在 raise 时自动 rollback，因此只有 flush 的更改不会持久化。
- **复现**: `authenticate` 失败时只调用 `record_login_failure` 后 raise → `failed_login_attempts` 永久为 0 → 5 次 lockout 失效。`rotate_refresh` replay 分支 `_revoke_all_active` UPDATE 后 raise → mass-revoke rollback → 被盗 refresh 防御失效。
- **修改位置**: `app/services/auth_service.py::authenticate` (紧接 record_login_failure) / `rotate_refresh` (紧接 replay UPDATE)。正常路径的 commit 仍由 router 负责。
- **回归 guard**: `tests/test_auth_login.py::test_wrong_password_returns_401_and_increments_counter`, `test_five_failures_lock_account_returns_423`, `tests/test_auth_refresh.py::test_refresh_replay_revokes_all_active`。移除 xfail strict。
- **类似类别检查目标**: 其他 router/service 中 UPDATE counter/audit row 后 raise 的代码 — 发现时需要相同 fix。
