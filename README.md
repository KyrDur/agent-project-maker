# Agent Project Maker

**从「做出一个 Agent」到「用评测证据验证改进」**

用自己的 API Key 创建通用 Agent，在模拟环境中试用，由模型自动测试和评分，亲自确认逐轮优化，并导出 AI 产品经理作品材料。

## 项目定位

这是一个 **Agent 模拟项目实践与评测平台**。成绩来自冻结用例下的实际执行和判定，不能代表真实客户效果、生产部署或未经验证的业务收益。项目完成表示实验、设计决策与材料完整，不设最低成绩门槛。

当前处于 Beta。功能实现、固定响应测试和真实模型验收分别记录；请以验收记录中的具体范围和结果为准。

## 三模型协作

| 角色 | 工作 |
|---|---|
| 模型 A：生成与执行 | 理解需求、生成指令和文本 Skill、执行 Agent、根据失败证据生成具体修改方案 |
| 模型 B：测试设计 | 生成评测计划、20 条正式用例、模拟数据及预期行为 |
| 模型 C：裁判与分析 | 根据实际输出评价内容、引用证据、分析失败与薄弱指标 |

三个角色使用当前用户的个人配置，分别选择提供商、模型和 API Key。也可以主动选择同一凭据用于多个角色。角色未配置、凭据不可用或调用失败时明确报错，不借用管理员密钥，不偷偷换模型。

程序负责检查格式、明确业务规则和模拟最终状态；模型 C 负责需要内容判断的指标。裁判不可用属于评测错误，不能当作通过。用户不需要手工评分，也不需要为自动测试集逐条填写抽查理由。

## 使用流程

1. 登录自己的账号，打开「个人 AI 配置」（`/settings/system-llm`），添加个人 API Key，配置 A、B、C。密钥加密保存并按账号隔离。
2. 通过对话说明任务目标、输入、预期产物、业务规则和成功条件。检查需求并填写确认理由；未知业务规则由用户补充或确认模拟假设。
3. 检查指令、所需模拟工具和文本 Skill，修改内容后确认能力方案及理由。简单任务可以只有指令，不强制增加工具或 Skill。
4. 创建 Agent 和不可变 V1。系统自动调用 B 生成并校验测试集，冻结需求、用例、初始数据、评分口径和模型配置，然后启动正式评测。
5. 在项目页选择版本和场景进行模拟聊天。默认正常场景，消息和模拟状态可恢复，能查看调用证据并重置。聊天不评分，数据与正式实验独立。
6. 查看逐例结果、失败和裁判依据。C 分析证据，A 提供 2–3 条具体方案，列出改动、依据和风险。
7. 选择方案、填写理由并预览差异，生成 V2，系统自动使用同一冻结实验回归。下一轮以 V2 为基础生成 V3，即使 V2 退步也不自动切换到历史最佳版本。每轮都需要人工确认，不连续自动优化。
8. 比较 V1→V2、V2→V3 和 V1→V3；如实记录提升、持平、退步及新增失败。没有证据支持进一步改进时，可以结束，保留继续迭代能力。
9. 导出报告、中文 AI 产品经理简历、面试题及 ZIP。它们共用实际版本、运行和用例证据，保留用户理由原文。

生成阶段失败会暂停并保留已确认内容，重试对应阶段。修改需求或模型配置需要开启新的实验范围；不同口径不可直接比较。

## Skill 与模拟工具

**Skill** 是供模型遵循的文本指南。需要时由 A 生成，用户可预览、修改和确认。新版本快照冻结正文、版本与哈希，运行及优化使用同一份文本。旧快照缺少正文时明确显示证据缺失，不从后来变化的文件补造。

**模拟工具** 用于按参数查询数据、修改模拟状态、记录调用，或按调用次数触发失败以验证恢复性重试。正式用例独立初始化环境；聊天会话内状态延续，重置后回到冻结初始状态。

本轮模拟路径不连接真实业务工具或 MCP，不执行脚本型 Skill。工具返回的实际数据决定 Agent 和裁判可观察到的证据，后台未返回的信息不能作为评分依据。

## 成绩与证据

- 分开显示本次结果、最新版本、历史最佳和项目完成状态。同分保留较早的历史最佳，候选版本不会自动覆盖运行中的 Agent。
- 区分任务通过、任务失败、执行错误和裁判错误；注明全部用例通过率的分母，同时展示成功执行用例中的任务通过率和指标覆盖数。
- 未评分项显示不可用，部分运行不能当作完整成绩。全部执行或裁判错误不构成有效实验。
- 保存实际模型标识、有效参数、模型返回内容、工具参数和结果、最终输出、终止原因，以及裁判来源和判定依据。失败、超时和调用次数限制保留已有证据，敏感值沿用脱敏机制。
- 报告和求职材料使用真实前后数据，退步也保留。求职材料仅覆盖 AI 产品经理。

## 本地开发

技术栈：Next.js 16、React 19、TypeScript、FastAPI、SQLAlchemy、PostgreSQL、Alembic、LangGraph/`deepagents` 0.7.11；后端检查工具 Ruff 0.16.5。

需要 Node.js 22、pnpm、uv 和 Docker。参考 [项目设置](docs/agent-project-setup.md) 配置数据库、认证与加密环境，新增存储通过 Alembic 迁移。环境中的模型密钥不替代用户的三个个人角色配置。

```bash
# 后端（先配置隔离的开发数据库）
cd backend
uv sync
uv run alembic upgrade head
uv run uvicorn app.main:app --host 127.0.0.1 --port 8001 --reload --reload-dir app
```

```bash
# 前端
cd frontend
pnpm install
pnpm preflight
pnpm dev
```

## 评分指标与依据

评分指标是针对已确认需求生成的项目规则，不是行业认证分数。新实验使用结构化评分规则：模型 B 提供中文名称、用途、需求原文出处与明确档位，模型 C 审查是否引入未确认的约束；程序验证来源与字段后冻结。规则审查失败会暂停并允许重试，不能用通用规则替代。

- 程序检查明确的格式、必要工具、禁止操作、参数、必要顺序和最终模拟状态；区分必须成功的操作与故障场景中的真实调用尝试。没有适用检查时不评分。
- 内容裁判逐条件选择 0／0.5／1，引用实际输出或工具记录，由程序计算指标分数。引用不存在、字段不完整或裁判不可用均计为裁判错误。v3 中关键条件未完整满足（0 或 0.5 档）时，该指标为 0，任务失败。
- v3 每条用例必须满足所有适用任务指标的冻结阈值和必要程序检查；表达偏好独立展示。权重字段仅用于历史兼容，不表示采用加权总分。
- 成绩分别展示任务通过、任务失败、执行错误、环境错误（执行错误子类）和裁判错误；全部用例通过率包含错误用例，指标平均得分只包含已评分用例，并标注覆盖数。未评分项显示不可用，部分运行不称为完整成绩。
- 逐例展示判定理由、档位和证据出处；报告、面试材料与导出使用同一份运行证据。历史实验保留当时的文字规则和成绩，不补造结构化档位，也不与新口径直接比较。

- v3 裁判逐条检查事实、建议和条件性陈述。新增无依据事实会使任务失败；回答不能引用自身证明真实性。事实支持按条数汇总，展示不支持、无法判断和模型抽取覆盖的限制。
- 新生成用例在冻结前，先程序执行参考路径，再由 C 审查参考答复、判据及适用性。缺少响应、未声明工具、不可执行参数或不可观测写操作阻止冻结；无工具任务不强制生成工具指标或工具失败类别。
- 可选每例重复 1 或 3 次。全部试验分别保存，展示分母、每轮通过率和波动；最佳版本按同口径全部有效运行汇总，同分保留较早版本。单次运行标注稳定性未验证。
- 可单独冻结验证集。未使用的验证集不进入 A 的优化或普通聊天；显式填写使用理由后，其相关运行统一标为已使用，不能继续声称未见验证。
- 报告、简历、面试和 ZIP 共用证据摘要及稳定引用。两个案例从实际运行选择，保留输入、模拟返回、错误、判定、改动及剩余问题。个人确认、系统生成与 Codex 演示分开；材料随证据变化显示过期。

本轮不计算 Hit@K、Recall@K、MRR。计算这些检索指标需要实际排序列表及相关性标注；固定模拟返回不能替代检索质量测量。结构化档位和规则审查已实现，真实模型的一致性与判断准确度仍需专门校准，不能由固定响应测试证明。

## 验证与当前限制

验证覆盖后端服务、Vitest、Playwright、类型、构建、国际化、无障碍和设计系统检查；PostgreSQL 迁移在隔离测试库验证。具体通过数、失败项与实验数据写入 [完整质量修补验收记录](docs/agent-project-quality-revision-acceptance-2026-10-06.md)。

**固定响应测试只验证执行和记录链路，不证明真实模型质量。** 四类项目（写作、客服、知识问答、纯对话）的真实模型完整验收必须使用页面配置的有效个人 Key；未完成时维持未验收状态。本轮实际调用 572 次，四类基线及历史新范围存在裁判、超时、环境或预算错误，完整验收尚未通过；新时限协议与实际迭代的待完成项见验收记录。

试用页面提供可编辑的示例输入；必填确认理由附有常驻说明和示例，示例不会自动填入贡献记录。模拟场景准备显示当前步骤及具体失败原因，失败后由用户重试，重新打开页面不会自动重试已失败的流程。重新生成评测方案时同时提供原方案和审核意见；历史失败与成绩保留。

以下不在本轮验收范围：真实业务系统接入、脚本执行、MCP 配置、大规模 benchmark、持续自动优化、生产部署和真人体验。只读作品分享链接是后续验收事项，本轮先完成本地材料和导出。

历史快照、固定返回用例继续可读；缺失的模型参数、Skill 正文或用户理由明确标记，不回填。原型遗留语言与功能文档仍在清理，不能把历史描述视为本轮已实现或已验收的能力。

本项目基于 natural-mold 原型演进，保留原始许可与 [第三方声明](NOTICES.md)。[原型技术说明中文译本](README_PROTOTYPE_ZH_CN.md) 保留历史来源，当前产品能力以本页与验收记录为准。


真实模型开发验收脚本位于 `backend/scripts/validate_agent_project_judge.py`、`validate_agent_project_live.py` 和 `validate_agent_project_snapshots.py`。它们使用项目所属用户的当前个人配置，并记录开发演示来源、实际调用量及预设上限。真实验收会新增模拟项目或新评分范围；裁判校准不改写项目成绩。运行前检查验收记录与预算，使用明确的项目 ID。 `validate_agent_project_live.py --instructions-only` 仅用于另建输出目录下的纯对话无工具/无 Skill 验收，记录实际能力数量；不会删除已有项目的能力来改变成绩。不要把固定响应通过数当作真实模型能力结果。
