# 可靠评测与模拟飞书验收

评测使用真实模型，外部工具只运行冻结的模拟数据，不连接真实飞书。

## 评测契约

- 工具集合来自 Agent 版本快照。用例不能临时注入新工具。
- `mock_tool_data.<tool>.rules` 按完整参数匹配，`responses` 按调用次数消费；每个用例单独保存状态。参数不匹配、响应耗尽、缺少模拟数据都会留下失败证据。
- `expected.tool_assertions` 检查参数和匹配调用次数，`tool_sequence` 检查完整调用顺序。只检查工具名称不能证明参数正确；没有可验证依据时显示“未评估”。
- “未评估”与“不适用”的分数为 null，不作为零分展示，不加入平均分。证据不完整时不能接受优化回归。
- 被测模型使用版本中的模型与参数，凭据失效时报错。Judge 的提供商、模型、端点和参数冻结到评测运行，回归沿用；凭据中不保存明文 Key。
- 评分与失败分析均收到实际工具参数、返回值、错误和调用顺序。

## 真实模型验收

在本机设置 `WEEKLY_LLM_API_KEY`、`WEEKLY_LLM_MODEL`，兼容 OpenAI 的服务还需设置 `WEEKLY_LLM_BASE_URL`。不要提交密钥。

从 `backend` 目录执行：

```shell
uv run python scripts/accept_weekly_project.py --output ../output/weekly-acceptance.json
```

脚本使用独立的内存 SQLite，创建测试账号、凭据、Agent 和测试集，运行基线、分析 Bad Case、生成并接受隔离实验中的优化提案、创建新版本，再运行冻结测试集回归。覆盖分页、重试、权限拒绝、空数据、缺失数据和重试后仍超时六种场景。模拟发布还检查目标群和正文事实。

脚本会在执行失败、没有新版本、优化未被质量规则接受或出现退步用例时返回非零退出码；结果仍写入报告供排查。实验提案自动接受只发生在这份隔离验收脚本里，产品中的提案仍走用户决策流程。

2026-09-27 留存的真实模型报告使用 `deepseek-flash`：相同冻结用例下，基线通过 3/6，回归通过 6/6，修复 3 例、退步 0 例，比较结论为 accepted。原始报告保存在本地 `output/weekly-acceptance.json`，不含模型 Key。本次续接核对了已有报告，没有重新调用模型；该报告早于新增的显式运行状态和版本 ID 字段。
