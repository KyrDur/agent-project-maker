# 评分规则修补验收记录

验证日期：2026-10-06。本记录补充之前的三模型验收，不改写历史实验。

## 实现与历史兼容

- 新生成的评分计划使用 rubric_version=2。每项指标保存中文名称、解释、确认需求的原文出处和适用范围。模型 B 拟定规则，程序检查出处，模型 C 审核是否增加未经确认的限制；失败明确报错、保留原计划并允许重试。
- 内容判据保存未满足、部分满足、完全满足三个锚点。C 返回 0、0.5 或 1 和实际证据引文，程序按适用判据计算平均分；关键判据为 0 时该指标为 0。缺判据、伪造引用或返回格式错误记为裁判错误。
- 工具指标由程序检查必要业务操作、参数、必要顺序、禁止操作和最终模拟状态。尝试调用与成功调用分别声明；工具失败后如实解释可以是有效恢复路径，不能凭尝试就判定业务操作成功。
- 格式指标仅检查明确声明的 JSON、精确输出或字符数上限。不存在相应检查时不评分，不赠送满分。内容判据按用例冻结适用范围；排除项必须有原因，任务完成判据不得排除。
- 所有适用指标均达到冻结阈值才算任务通过，不生成任意加权质量总分。页面分别展示任务通过、任务失败、执行错误、裁判错误，全部用例通过率和成功执行用例中的通过率。指标均分以 /100 显示，另列覆盖数、未评分数、不适用数；部分运行明确标记。
- 评测、报告、作品集和导出使用实际来源运行的冻结规则。自定义指标显示保存的中文名称，旧 compliance_escalation 使用中文解释；旧快照没有判据时明确说明。历史摘要、哈希及原分数不重算、不补造。
- 当前没有检索排序列表和相关性标注，不展示虚构的 Hit@K、Recall@K、MRR。业务评分并不等于检索指标或行业标准。
