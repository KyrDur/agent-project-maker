# 优化操作与可读性修复验收（2026-10-06）

## 真人试用发现的问题

电商客服项目已接受 V1 的优化方案并创建 V2，但 V2 回归仍在运行。前端使用部分用例结果开放失败分析和方案生成；后台以 `422 optimization_requires_semantic_run` 拒绝未完成的评测，界面将其显示为笼统的“优化无法完成”。此次拒绝不是模型调用失败。

运行按钮直接显示 UUID 前八位，方案展示用例编号和 `instructions`、`workflow` 等内部标识，用户无法理解对应版本与修改内容。

## 修复范围

- 运行按钮显示版本、状态、时间，并标识当前选择。报告选择器也使用可读标签。
- 正在运行的评测显示已完成用例数，禁止分析或生成下一轮优化；结果不完整的运行提供说明。已有轮询继续更新进度和操作状态。
- 切换评测运行时重新挂载优化表单，清除上一运行的错误和选择理由。
- 按后台错误码显示原因和处理方式，可恢复的生成失败保留原请求 ID 重试。
- 方案显示关联用例名称、中文能力和修改目标；相关失败分析折叠展示。用户决策理由与历史证据保持原样。
